# Phase 3 — UI Design Contract

> Visual and interaction contract for transit: stop tags, stop card, drawer departure rows, vehicle markers, edge pointers and the disruption readout. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Extends `02-UI-SPEC.md` (approved), which extends `01-UI-SPEC.md`. Everything there stays binding unless a row below says "changes". Sources: 03-CONTEXT.md D-01..D-24 (locked), 03-RESEARCH.md (payload shapes, web pitfalls), the existing code in `web/src` (class names and tokens quoted below are the real ones). Items marked (default) are researcher choices inside CONTEXT "Claude's Discretion".
> Target: iPhone portrait standalone PWA, dark only. Reference viewport 393 x 852 pt, top safe inset 59, bottom safe inset 34.

## Design System

| Property | Value |

| Font | Unchanged: Silkscreen (card and sheet titles only), JetBrains Mono 400/700 with `font-variant-numeric: tabular-nums` on every countdown, distance and walk time |

### Sprites added to `icons.svg` (original art, drawn for this project)

All are outline glyphs that must stay readable at 16px. Each `<use>` host needs `fill: none; stroke: currentColor; stroke-width: 2` set in CSS (iOS Safari does not inherit it from the sprite root; see the `.recenter svg` comment in `map.css`).

| Symbol id | Drawing |
|-----------|---------|
| `stop-train` | Front view of a train: upright rectangle 12 wide x 14 tall, one horizontal window bar across the upper third, two square headlight dots near the bottom, and two short rails splaying outward below the body |
| `stop-tram` | Front view of a tram: rectangle 12 x 12, one wide window, a single straight pole rising from the roof centre to a short horizontal overhead-wire bar at the top of the grid |
| `stop-bus` | Front view of a bus: rectangle 14 x 12, a wide windscreen bar, two square wheel stubs below the bottom corners, two short mirror stubs at the upper sides |
| `veh-tram` | Side view: long low rectangle 18 x 8, three square windows, an angled pantograph line from the roof to a short wire bar |
| `veh-bus` | Side view: rectangle 18 x 10, one window strip, two square wheels cut into the bottom edge |
| `warn` | Triangle outline (point up), a vertical bar and a square dot inside |
| `pointer` | A solid arrowhead (filled triangle, `fill: currentColor`) pointing straight up, 12 wide x 14 tall, centred in the grid so it rotates about its centre |

No `veh-train` symbol this phase: there are no train markers (D-20). The service worker already precaches `icons.svg`; nothing else to cache.

### Accent (blood red) reserved for, Phase 3 additions

The Phase 1 and Phase 2 lists stay. Phase 3 adds exactly:

1. **One leave-now drawer row** (D-09): left marker `--c-red`, countdown `--c-red`, and a `LEAVE NOW` chip (`--c-red-deep` fill, `--c-on-red` 700). At most one row at a time (see Drawer rows).
2. **Service-stopping disruptions only** (D-17: cancelled departure, suspended route, closed stop, buses replacing trains; server sends `severity` 3):
   - the `warn` glyph in `--c-red` on the affected drawer row, stop tag badge, card line and readout;
   - the disruption readout frame `--c-red`;
   - the card alert block and the sheet's `NO SERVICE` chip: `--c-red-deep` fill, `--c-on-red` 700 text;
   - the `CANCELLED` chip on a cancelled departure line (same chip style);
   - the 4px left marker of that disruption's sheet row.

Never red: stop tag frames and chips, vehicle markers (D-12: blue, never red, including estimated and stale ones), edge pointers, `LIVE` / `SCHED`, delays, detours, planned works, "none nearby", no-key and error states, the stop and vehicle card frames and titles. Transit items never use the Phase 2 `near` class: the red within-30 m treatment stays cameras-only.

Drawer red rule (changes the Phase 1 generic rule for transit only): transit departure rows and disruption-end rows are **excluded** from the generic `urgent` (< 15 min) rule, or every tram would be red. While a leave-now row is red, the generic soonest-urgent row keeps its red left marker but loses its red countdown text, so the drawer never has two red countdowns.

## Stop Tags (TRAN-01, D-01..D-05, D-13)

One tag per stop item in the `transit_stops` layer that has a Point `geom` (at most 1 train + 2 tram + 2 bus, occasionally 6). Built by the existing `TagLayer.makeEl` path with a per-kind descriptor.

### Anatomy (class `map-tag stop full`)

| Part | Spec |
|------|------|
| Icon box | `.tag-icon`, `--tag-stop` 40 x 40, 1px `--c-blue`, `--c-panel`, glyph 24px `--c-blue`: `stop-train`, `stop-tram` or `stop-bus` |
| Label chip | `.tag-label`, joined to the icon box (shared border), 40px tall, 1px `--c-blue`, `--c-panel`, padding 1px `sm`, `max-width: 144px`, two lines stacked (`flex-direction: column; justify-content: center`): line 1 `.stop-name` short stop name with ellipsis; line 2 `.stop-meta` `{distance} · {walk}` e.g. `409 m · 6 min` |
| Tick | Existing `.tag-tick`, 1px x 8px `--c-blue`, below the 40px box |
| Hit area | 48 x 48 wrapper plus the chip; `role="button"`, `tabindex="0"` |
| Warning badge | Only when an alert applies to the stop or to a route in its departures: a 16 x 16 `--c-panel` square with the `warn` glyph 16px, overlapping the icon box's top-right corner by 8px (`.tag-warn`). Glyph `--c-text` for info alerts, `--c-red` for service-stopping |
| Pressed | Icon box and chip fill `--c-surface` (existing rule) |
| Selected | Existing 4px `--c-blue` bar under box and chip |
| Flip | Existing `flip` class and `labelSide()` logic: chip goes left when it would clip the right edge |
| Stacking | `.map-tag.stop { z-index: 3 }`, vehicles 2, near cameras 1, other cameras 0. David's marker stays above all |

Stops are **always** `full`: never compact, never collision-demoted, at every zoom. When two stop chips overlap (paired bus stops across a road), the stop with the smaller screen x flips its chip left and the other keeps right; if they still overlap the nearer stop draws on top. No other handling.

### Label values

| Value | Rule |
|-------|------|
| Short stop name | One pure function `shortStopName(name)` used for tags, pointers, drawer rows and vehicle cards: take the text before the first `/`; drop a trailing ` Railway Station` or ` Station`; drop a trailing ` #N` stop number; abbreviate whole words Street→St, Road→Rd, Avenue→Ave, Highway→Hwy, Parade→Pde, Drive→Dr, Boulevard→Bvd; trim. `Flinders Street Station/Swanston St #13` → `Flinders St`; `Bourke Street Mall/Elizabeth St #3` → `Bourke St Mall`. The full name appears only in the stop card |
| Distance | Existing `fmtDistance()`: `42 m`, `1.2 km` |
| Walk time | `N min`, N = max(1, ceil(walk seconds / 60)). GPS and search origins: walk seconds = round(live distance in metres x 0.936) recomputed on each reconcile, so it shrinks as David walks. Saved-place ("server") origin: the server's `detail.walk_s` and `detail.distance_m` |
| Countdown | None on the tag. The stop is a positioned fact (same rule as cameras, Phase 2 D-14); its countdowns are the drawer rows and the card, one tap away |

`aria-label`: `{Train station|Tram stop|Bus stop}, {full name}, {spoken distance} away, {N} minute walk` plus `, disruption` or `, service stopped` when badged.

### "None nearby" (D-03)

A mode with no stop inside its limit has no tag and no pointer. It appears as one quiet drawer row per missing mode (see Drawer rows, state `none`), so the mode is never silently missing.

## Label Budget (D-13, extends Phase 2 "Budget and promotion")

One shared budget, no separate transit budget. Rank order in `rankTags`: priority first (stop 0, vehicle 1, camera 2), then the existing within-30 m / distance order inside a priority.

| Step | Rule |
|------|------|
| 1. Stops | All stops (max 6) are labelled, always. They count toward the budget |
| 2. Vehicles | Up to 8 vehicle markers, soonest arrival first. A vehicle's route badge is its label and counts as one labelled tag. Vehicles are never demoted to a badge-less icon; vehicles beyond 8 are not rendered |
| 3. Cameras | Fill what is left of the cap: 8 labelled tags below zoom 17.5 (`BASE_FULL`), 20 at or above it (`MAX_FULL`). Within-30 m cameras first, then nearest. Cameras that do not fit render compact (icon only), exactly as Phase 2 |
| Guarantee | The up-to-3 red within-30 m cameras keep their labels even when stops and vehicles have used the cap. Worst case 6 + 8 + 3 = 17, so the hard maximum of 20 labelled tags is never exceeded |
| Collision | Stops and vehicles are exempt from overlap demotion. A camera label that overlaps a stop chip, a vehicle marker or a higher-ranked camera label is demoted to compact |
| Marker cap | `MAX_TOTAL` 60 DOM markers unchanged; stops and vehicles are taken first |
| Re-evaluation | Unchanged: on profile change and on `moveend`, debounced 100 ms. Vehicle position updates move markers without re-ranking |
| Tap overlap | Overlapping 48px hit areas: nearest centre wins; a stop wins a tie against a vehicle or camera |

## Stop Card (D-07, D-08, D-10, D-16)

Opened by tapping a stop tag (or a drawer departure row, or an edge pointer after the map arrives). Uses the existing `Card` (role dialog, not modal, one at a time, leader line, same placement and close rules) with class `card transit` and width `--card-w-wide` (240px). Frame and title are always `--c-blue`.

`CardContent` gains an optional `sections` list rendered between `extra` and `secondary`; nothing else in `card.ts` changes. The card's countdowns tick once a second while it is open (subscribe to the existing `ticker.ts`; update text nodes only, never rebuild the card on a tick).

### Layout

```
TRAM STOP                              .card-title      Silkscreen 16, blue
Bourke Street Mall/Elizabeth St #3     .card-primary    Body 16, max 2 lines
27 m · 1 min walk                      .card-extra      Body 16, tabular-nums

96 to St Kilda Beach                   .card-dep-head   Label 12 / 700
03:12  LIVE · delayed 3 min            .card-dep
11:40  SCHED                           .card-dep
86 to Bundoora RMIT                    .card-dep-head
00:40  LIVE · too late                 .card-dep.missed
08:05  LIVE                            .card-dep

[!] Route 96: delays up to 10 min      .card-alert      Label 12, max 3 lines
    ends in 2h 10m                     .card-alert-end  Label 12 dim

Source: PTV                            .card-caveat     Label 12 dim
```

| Part | Spec |
|------|------|
| Title | `TRAIN STATION`, `TRAM STOP` or `BUS STOP` |
| Primary | Full stop name from the server, 2-line clamp |
| Extra | `{distance} · {N} min walk` |
| Groups | One group per route and direction: head `{route number} to {destination}`; trains `{route name} line to {destination}` when `detail.route_name` exists, else `to {destination}`. Groups ordered by their soonest departure. `margin-top: sm` before each head |
| Lines | The next 2 departures of each group. **Cap 8 departure lines** (4 groups); when more groups exist, one final Label 12 dim line `+{n} more routes` |
| Line anatomy | Flex row, gap `sm`: `.dep-count` (fixed 48px, `fmtCountdown`) · `.dep-mark` (`LIVE` 700 `--c-text` or `SCHED` 400 `--c-dim`) · `.dep-note` (`--c-dim`). A long note wraps to a second line aligned under the mark; it is never ellipsised |
| Note content, in order | Trains: `plat {n}` (or `at plat {n}` when `at_platform`); then `delayed {N} min` when `delay_s` >= 60 or `{N} min early` when `delay_s` <= -60 (N = round(abs(delay_s) / 60)); joined with ` · ` |
| SCHED line | Countdown weight 400 (still `--c-blue`), mark `SCHED` dim. Never shows a delay note |
| Uncatchable line (D-08) | Class `missed` when departure minus walk time is more than 30 s in the past: every span `--c-dim`, weight 400, and the note is replaced by `too late`. Dimming is paired with the words, so colour is not the only signal |
| Cancelled line | Countdown `--c-dim`; the mark is replaced by a `CANCELLED` chip (`--c-red-deep` fill, `--c-on-red` 700, padding 0 `xs`); no note |
| Warning mark on a line | A 16px `warn` glyph before the mark when one of the line's `disruption_ids` is shown: `--c-text` for info, `--c-red` for service-stopping |
| Alerts | After the groups, up to 2 alerts (service-stopping first, then soonest end): 16px `warn` glyph + PTV title text (trimmed to 120 chars, 3-line clamp). When the end time is known a second line `ends in {countdown}`. Service-stopping alert: the whole block gets `--c-red-deep` fill, `--c-on-red` 700 text, white glyph, padding `xs` `sm`. More than 2: a Label 12 dim line `+{n} more · see disruptions` |
| Caveat | `Source: PTV` (the full licence line lives in the drawer footer and the disruption sheet) |
| Links | None. Alert `url` values are never rendered: the PWA does not link out |
| Height | The card must fit between the readouts and the drawer peek (about 420px on the reference phone). If its content is taller, the groups block scrolls inside the card (`max-height` set from the available space through `--card-max-h`, `overflow-y: auto`, `overscroll-behavior: contain`) |

### Stop card states

| State | Shown in place of the groups |
|-------|------------------------------|
| Loading (departures layer `pending`, PTV state `ok`) | One Label 12 dim line `Departures · loading` |
| No key (PTV state `no_key`) | `Departures · PTV key not set` |
| Error with nothing cached | `Departures · unavailable` |
| No upcoming departures for this stop | `No services listed` |
| Stale (layer `stale` or data older than 120 s) | Groups stay, at `--o-stale` opacity, countdowns keep ticking; a Label 12 dim line `Departures {age}` using the existing `ageTag()` text, e.g. `Departures 3m old` |
| Offline | Same as stale; the OFF-GRID banner covers the reason |
| Next service over 1 h away | A normal line; `fmtCountdown` gives `5h 12m` |

The title, name and distance lines always render (they come from the static stop store and need no key).

## Drawer Departure Rows (D-06, D-08, D-09, D-10, D-16)

Existing `next-list` row anatomy (two `.row-line`s) with a `transit` class and extra spans. Selection logic lives in `model.ts` in its own transit branch.

### Which rows exist

| Rule | Spec |
|------|------|
| Grouping | One row per stop and direction of travel (`group = "{stop}:{direction}"`), row id `transit:{stop}:{direction}` so the row updates in place when it rolls to the next service |
| Caps (default) | At most 2 rows per stop (the 2 direction groups with the soonest catchable departure) and at most 6 departure rows in total. Everything else is in the stop card |
| Catchable pick (D-08) | `leaveIn = target_ts − walk_s − now`. A departure is catchable while `leaveIn > −30 s` (the walk time already carries a 30% detour allowance). The row shows the first catchable, non-cancelled departure of its group. Recomputed every tick on the phone |
| Nothing catchable | The row shows the group's soonest departure in the `missed` state (never blank) |
| Sort | With all other rows by departure time (`targetMs`), as today |
| Corner readouts | Transit rows are excluded from `cornerRows()`; the two top-left readouts stay sun and UV |
| Rollover | When the shown departure leaves or is missed, the text switches to the next one with no expiry pulse. The Phase 1 expiry pulse plays only when a whole row disappears |
| Tap | New: tapping a departure row collapses the drawer to peek, eases the map to that stop (600 ms; `jumpTo` under reduced motion) and opens its stop card. Pressed state: row background `--c-surface`. Rows are already 48px or taller |

### Anatomy

```
Tram 96 to St Kilda                              06:12     line 1: .row-name / .row-count
[!] tram · LIVE · delayed 3 min        leave in 01:40      line 2: .row-kind group / .row-leave
```

| Part | Spec |
|------|------|
| Name | `{Mode} {route number} to {short destination}`: `Tram 96 to St Kilda`, `Bus 907 to Mitcham`. Trains have no number: `Train to Flinders St`. Existing ellipsis |
| Main countdown | Time until departure, `fmtCountdown` unchanged (so 6 min 12 s renders `06:12`, an hour or more `1h 4m`). 20px, 28px on the first row. LIVE weight 700, SCHED weight 400, both `--c-blue` |
| Line 2 left (`.row-kind`, may ellipsis) | Optional 16px `warn` glyph, then `{mode} · {LIVE|SCHED}`, then for trains ` · plat {n}`, then ` · delayed {N} min` / ` · {N} min early`. `LIVE` is its own span `.row-live` (700, `--c-text`); `SCHED` is `.row-live.sched` (400, `--c-dim`) |
| Line 2 right (`.row-leave`, never truncated) | `leave in {fmtCountdown(leaveIn)}`: words `--c-dim`, value 700 `--c-text` tabular-nums. When the row is stale, ` · {age}` is appended (`leave in 01:40 · 3m old`). The generic `.row-fresh` age tag is not shown on fresh transit rows: `LIVE` / `SCHED` is the freshness statement |
| Left marker | Existing 4px `--c-blue` |

### States

| State | Condition | Treatment |
|-------|-----------|-----------|
| Normal | `leaveIn` > 60 s | As above |
| Leave now (D-09) | 60 s >= `leaveIn` > −30 s, on the soonest-departing row in that window | Class `leave-now`: left marker `--c-red`, countdown `--c-red`, `.row-leave` becomes a `LEAVE NOW` chip (`--c-red-deep` fill, `--c-on-red` 700, padding 0 `xs`). One hard switch, no blink, no pulse. Lasts at most 90 s per departure |
| Leave now, second row | Another row is also in the window | No red: `.row-leave` reads `leave now` in 700 `--c-text`. Only one red row at a time |
| Missed | No catchable departure in the group | Class `missed`: name and countdown `--c-dim`, weight 400, marker `--c-frame`; `.row-leave` reads `too late to catch` in `--c-dim`. Never red |
| SCHED | `detail.live` false | Countdown weight 400, `SCHED` mark dim |
| Disrupted | A shown disruption matches the row's route or stop | `warn` glyph at the start of line 2: `--c-text` for info, `--c-red` for service-stopping. Row colours otherwise unchanged |
| Stale | Layer `stale` or item older than `stale_after_s` (120 s) | Existing `.row.stale` (opacity 0.55, dim text), age appended as above. A stale row is never red |
| None nearby (D-03) | A mode has no stop inside its limit | One row per missing mode, class `transit none`: name `No tram stop within 800 m` (`No train station within 1.5 km`, `No bus stop within 500 m`) in `--c-dim`; countdown slot `--` in `--c-dim` at Label 12; line 2 `{mode} · none nearby`; marker `--c-frame`; no tap handler. Sorted last (no target time) |
| Status row | Stops exist but there are no departures to show for any of them | A single row id `transit:status`, class `transit none`, name `Departures`, countdown slot `--`, line 2 one of: `loading` · `PTV key not set` · `unavailable` · `no services listed`. No tap handler |
| Disruption end row (D-16 exception) | A shown disruption has a known end within 24 h | At most 2 rows: name `{Mode} {route} disruption` (`Train disruption` without a number), main countdown = time to the end, line 2 `disruption · ends`, normal blue row, excluded from the urgent rule, tap opens the disruption sheet |

Row `aria-label`, refreshed once a minute like today: `{name}, departs in {countdown}, {live|scheduled}, leave in {leave countdown}` (or `leave now`, `too late to catch`), plus `, disruption` / `, service stopped`.

Peek: a transit row can be the Display row; its two lines fit the existing 64px.

## Vehicle Markers (TRAN-03, D-11, D-12, D-20)

One marker per item in `transit_vehicles` with a Point `geom`, max 8. Trams and buses only; no train markers this phase.

### Anatomy (class `map-tag vehicle`, plus `est` or `fading`)

| Part | Spec |
|------|------|
| Icon box | `.tag-icon`, `--tag-veh` 24 x 24, 1px solid `--c-blue`, `--c-panel`, glyph 16px `--c-blue`: `veh-tram` or `veh-bus` |
| Route badge | `.veh-badge`, joined to the right of the icon box (shared border), 24px tall, min-width 24px, padding 0 `xs`, 1px solid `--c-blue`, `--c-panel`, Label 12 / 700 `--c-text`, tabular-nums, text = route number (`96`, `907`) |
| No tick, no name chip, no countdown label | The box centre is the position. No heading arrow (bearing exists only for some buses; an arrow on some markers and not others would mislead) |
| Hit area | 48 x 48 centred on the marker; `role="button"`, `tabindex="0"` |
| Selected | 4px `--c-blue` bar under box and badge |
| Colour | Blue and white only. Never red, in any state |

### Estimated marker (D-20: `detail.pos_src === "est"`)

Must be visibly different without relying on colour. Class `est`:

| Change | Spec |
|--------|------|

## Edge Pointers (D-14)

New module `web/src/map/edge-pointers.ts`. One pointer per stop whose tag is off-screen. Vehicles and cameras never get pointers.

### Anatomy (`button.edge-pointer` inside a fixed `div.edge-pointers`)

| Part | Spec |
|------|------|
| Container | `position: fixed; inset: 0; z-index: 4; pointer-events: none` (below `.map-controls` 5, the drawer 6, leader 7 and card 8) |
| Chip | `--pointer-h` 32px tall, `max-width: --pointer-max-w` 208px, 1px `--c-blue`, `--c-panel`, padding 0 `sm`, gap `xs`, `pointer-events: auto`, positioned with `transform: translate3d(var(--x), var(--y), 0)` |
| Arrow | `pointer` glyph 16px `--c-blue`, `transform: rotate(var(--rot))`; 0deg points to the top of the screen. Only the arrow rotates; text stays upright |
| Mode glyph | 16px `stop-train` / `stop-tram` / `stop-bus`, `--c-blue` |
| Text | `.ptr-name` short stop name `--c-text` (shrinks, ellipsis) then `.ptr-dist` ` · 900 m` `--c-dim` (never shrinks). Example: `Flinders St · 900 m` |
| Hit area | The button is 48px tall (the 32px chip centred in it by 8px transparent padding) and at least 48px wide |
| Pressed | Chip fill `--c-surface` |
| Fade | 120 ms opacity in and out; instant under reduced motion |

### Placement

| Rule | Spec |
|------|------|
| Clamp rectangle | Left and right: `sm` (8px) plus `env(safe-area-inset-left/right)`. Top: the bottom of the `.readouts` block (or of the location strip if readouts are empty) plus 8px, which already sits below the top safe area, title bar and OFF-GRID banner. Bottom: the drawer's top edge (`--drawer-h`, which includes the bottom safe area) minus 8px |
| Off-screen test | A stop is on-screen when `map.getBounds()` contains it **and** its projected point is inside the clamp rectangle. Otherwise it is off-screen (a tag hidden under the HUD or drawer counts as off-screen). Hysteresis: a pointer appears as soon as the point leaves the rectangle and is removed only when the point is 16px inside it |
| Direction | Screen angle = geographic bearing from `map.getCenter()` to the stop, minus `map.getBearing()`. Do **not** derive it from `map.project()`: at pitch 60 a stop behind the camera projects to mirrored coordinates |
| Position | Cast a ray at that angle from the clamp rectangle's centre and take where it meets the rectangle's edge; place the chip fully inside the rectangle touching that edge (left edge: chip's left side on it; right edge: chip's right side on it; top or bottom: centred on the hit point, then clamped horizontally) |
| Recenter button | When `.recenter` is visible, a pointer whose rectangle would touch it (with an 8px gap) is moved up until clear |
| Pointer-to-pointer | Place nearest stop first. A pointer that would overlap one already placed (4px gap) slides along its edge in 36px steps (down on side edges, right on top and bottom, reversing at the rectangle's end). If no free slot is found it is not shown. At most 5 pointers |
| Cards | The card's `avoid` list gains the pointer rectangles, so a card prefers a side that does not cover one. A card may still cover a pointer (card is above) |
| When hidden | All pointers are removed when: the clamp rectangle is under 144px tall (drawer at full), a sheet is open, the origin is null, or the place has no transit |
| Recompute | On `move` (throttled to one rAF), on `moveend`, on profile or layer change and on resize. At most 6 projections per frame |
| Distance text | The same distance the stop tag shows (live haversine for GPS and search, server `distance_m` for saved places) |

### Tap

Follow turns off and the recenter button appears (as for any user pan). `map.easeTo({ center: stop, duration: 600 })` keeps zoom, pitch and bearing, with the existing bottom padding so the stop lands in the visible map area; `jumpTo` under reduced motion. When the move ends the stop's card opens. `aria-label="Show {full stop name}, {spoken distance} away"`.

## Accessibility

- Touch targets: stop tags, vehicle markers, edge pointers, the disruption readout, departure rows and the sheet's `Close` are all at least 48 x 48 (visuals 24 to 40px with transparent padding).
- Contrast: all text is `--c-text` (about 17:1), `--c-dim` (about 6.5:1) or `--c-blue` (about 5.7:1) on `--c-panel`; `--c-on-red` on `--c-red-deep` is about 11:1. Red at 4.4:1 is used only for glyphs, frames and 20px+ bold countdowns.
- Colour is never the only signal: LIVE vs SCHED is a word plus weight; uncatchable is dim plus `too late`; leave-now is red plus the `LEAVE NOW` words; service-stopping is red plus `NO SERVICE` / `CANCELLED` / the alert text; an estimated vehicle is dashed, tilde-prefixed and says `EST`; a stale row shows its age.
- Labels: every tag, marker, pointer, row and the readout has the `aria-label` given in its section. Countdowns are not `aria-live`; labels refresh once a minute (existing pattern). The OFF-GRID banner stays the only live region.
- Keyboard: Tab order adds, after the camera tags: stop tags (nearest first), vehicle markers, edge pointers, the disruption readout. Enter or Space activates. Escape closes the card or sheet.
- Focus: the stop and vehicle cards follow the existing card rule (focus in on open, back to the tag on close); the sheet traps focus while open.
- Reduced motion: all glides, fades, eases and the sheet slide become instant (see Motion).
- Fixed pixel sizes (no Dynamic Type), as before.
