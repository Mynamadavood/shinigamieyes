    - departure at now+1 min with walk 2 min (leaveIn -60 s, beyond the 30 s grace) is skipped; the row shows the next one

    - all departures in a group uncatchable -> row shows the soonest with `missed true`, leaveText "too late to catch", never red
    - cancelled departures are skipped for the pick
    - leave-now window 60 s >= leaveIn > -30 s: only the row with the soonest departure in the window gets `leaveNowRed true` (leaveText "LEAVE NOW"); a second row in the window gets `leaveNow true`, `leaveNowRed false`, leaveText "leave now"
    - stale rows (layer stale or item older than 120 s) are never leaveNowRed and leaveText gets " · {ageTag}" appended
    - kindTag "tram · LIVE" for live, "bus · SCHED" for scheduled; note for trains "plat 4" or "at plat 4", then "delayed 3 min" when delay_s >= 60 or "2 min early" when delay_s <= -60, joined with " · "; SCHED rows never carry a delay note
    - caps: a stop with 3 direction groups yields 2 rows (the 2 with the soonest catchable departure); 5 stops x 2 groups yield 6 rows total (soonest kept)
    - the status row from 03-04 disappears as soon as at least one departure row exists
    - transit rows still never set `urgent` or `redCountdown`; when a leaveNowRed row exists the generic soonest-urgent row keeps `urgent` but has `redCountdown false`
  </behavior>
  <action>Per D-06, D-08, D-09 and D-10, inside `transitRows`:
- Collect `transit_departures` items whose `target_ts*1000 > nowMs - 120_000`. Group them by `item.group` and, inside each group, sort by target_ts.
- Pick the first item that is not cancelled with `leaveIn = target_ts*1000 - detail.walk_s*1000 - nowMs > -CATCH_GRACE_MS`. If none, fall back to the soonest non-cancelled item with `missed = true`.
- Build the RowVM: `id "transit:" + group`, `name item.name`, `countdownText fmtCountdown((target - now) / 1000)`, `targetMs`, `kindTag "{mode} · {LIVE|SCHED}"`, `note`, `leaveText "leave in " + fmtCountdown(max(0, leaveIn) / 1000)`, `live`, `missed`, `stopId detail.stop_id`, `transit true`, `stale` via isStale and `ageTag`.
- Apply the caps: per stop, keep the 2 groups with the soonest departure; overall, keep 6.
- Mark leave-now: rows with `LEAVE_NOW_MS >= leaveIn > -CATCH_GRACE_MS`, not missed, not stale. The one with the smallest targetMs gets `leaveNowRed`; the others get `leaveNow`.
- Then, in selectVisible, if any row is leaveNowRed, clear `redCountdown` on the generic row (the UI-SPEC rule: never two red countdowns).

All selection happens per call (each tick), from absolute `target_ts`.</action>
