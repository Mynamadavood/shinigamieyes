# Phase 1 — UI Design Contract

> Visual and interaction contract for the flat HUD slice. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Sources: CONTEXT.md D-01..D-17 (locked), 01-RESEARCH.md (stack), hero-eyes.png and nethack-view.png (style). Items marked (default) are researcher choices where upstream left discretion.
> Target: iPhone only, standalone PWA, portrait, dark only (no light mode, no `prefers-color-scheme` branch).

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (vanilla TS + Vite, plain CSS custom properties). shadcn gate: not applicable, stack is not React/Next |
| Preset | not applicable |
| Component library | none (hand-written DOM modules) |
| Icon library | none in Phase 1. Status glyphs are text or CSS (`●`, `▲`, `×`). No icon font, no SVG sprite sheet |
| Font (titles) | Silkscreen 400 and 700, `@fontsource/silkscreen` self-hosted woff2, `font-display: block`, titles only |
| Font (body) | JetBrains Mono 400 and 700, `@fontsource/jetbrains-mono` self-hosted woff2, `font-variant-numeric: tabular-nums` on every countdown and age tag |
| Fallbacks | `"Silkscreen", ui-monospace, monospace` and `"JetBrains Mono", ui-monospace, "SF Mono", monospace` |
| Tokens file | `web/src/styles/tokens.css` (`:root` custom properties). All other CSS references tokens only, no literal hex or px outside it. Phase 2+ extends this file, never forks it |
| Rendering | `-webkit-font-smoothing: antialiased`. `image-rendering: pixelated` for any bitmap. Frames use 1px solid borders, no border radius (0), no box shadows, no gradients |
| Viewport | `viewport-fit=cover`, `100dvh`, `meta theme-color #000000`, `apple-mobile-web-app-status-bar-style: black-translucent`, root padded with `env(safe-area-inset-*)`. Disable text zoom on inputs by keeping input font-size at 16px |

## Spacing Scale

Declared values (all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gap between countdown and age tag, glyph gaps, frame-to-content nudge |
| sm | 8px | Row inner vertical padding, chip padding, gap between name and kind label |
| md | 16px | Screen horizontal gutter, row horizontal padding, gap between rows |
| lg | 24px | Section padding, title bar to list gap |
| xl | 32px | Empty/error state block padding |
| 2xl | 48px | Minimum touch target height (rows, buttons, preset chips, search field) |
| 3xl | 64px | Reserved for Phase 2 drawer peek height, not used in Phase 1 |

Exceptions: touch targets are 48px minimum (above Apple's 44pt). The frame line is 1px (border width, not a spacing token). Bottom padding adds `env(safe-area-inset-bottom)` on top of `md`. The OFF-GRID banner sits below the top safe-area inset and pushes content down, it never overlays it.

## Typography

Exactly 4 sizes, 2 weights (400 regular, 700 bold) across both families.

| Role | Family | Size | Weight | Line Height |
|------|--------|------|--------|-------------|
| Label (age tag, kind tag, banner, footer) | JetBrains Mono | 12px | 400 | 1.5 (18px) |
| Body (item name, input text, preset chips, buttons) | JetBrains Mono | 16px | 400 | 1.5 (24px) |
| Heading (title bar, section header, banner lead word) | Silkscreen, UPPERCASE | 16px | 700 | 1.2 (rounded to 20px) |

> Heading and Body deliberately share 16px (distinguished by font family and weight), so there are 4 distinct sizes across 5 roles. Verified contrast on `#000000`: `--c-dim #7E92A3` ≈ 6.5:1, `--c-blue #5E8AA8` ≈ 5.7:1 (≈ 5.1:1 on `--c-surface`), so both pass 4.5:1 at 12px.
| Countdown | JetBrains Mono | 20px | 700 | 1.2 (24px) |
| Display (countdown of the single most urgent item, row 1 only) | JetBrains Mono | 28px | 700 | 1.2 (34px, rounds to 36px) |

Rules:
- Silkscreen only appears in: title bar text, section headers ("NEXT", "SOURCES" later), and the word `OFF-GRID`. Never for item names, countdowns, or body copy. Letter-spacing 0.08em on Silkscreen.
- Pixel font stays on whole-number px sizes (16px) to remain crisp. No fractional scaling.
- Item names and all copy are sentence case, except Silkscreen headings which are uppercase.
- Label uses the dim text color (see Color), never red except when the row is urgent-red (see Item Row).

## Color

Dark only. Palette follows D-03: blood red scarce, desaturated cold NetHack blue for neutral, white text, no pink or magenta (hero-eyes pink `#800080` and `#FF00FF` are recoloured to red).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#000000` | Page background, list background, safe-area fill |
| Secondary (30%) | `#08131D` (surface), `#1C3A52` (frame/hairline), `#5E8AA8` (neutral blue for glyphs, kind tags, neutral countdown) | Row surface on press, frame lines, rules, neutral item emphasis, chips |
| Accent (10%) | `#E0202A` blood red (pressed/glow variant `#7A0F15`) | Reserved list below |
| Destructive | none in Phase 1 (no destructive actions exist) | Do not use red for delete. If a later phase adds one it gets its own token |
| Text primary | `#E8EEF4` | Item names, input text |
| Text dim | `#7E92A3` | Age tags, kind tags, placeholders, stale items. Must keep contrast ≥ 4.5:1 on `#000000` |
| Text on red | `#FFFFFF` only, at weight 700 (≈4.76:1 on `#E0202A`). Black (≈4.4:1) and `#E8EEF4` (≈4.1:1) fail and must not be used on red |

Accent reserved for (and nothing else):
1. Title bar background fill (the hero "EYES" bar recoloured, 1 element, top of screen).
2. The OFF-GRID banner background.
3. A row's countdown text and left edge marker when the item is urgent (less than 15 min to target, or an active expiry pulse).
4. The expiry pulse flash (D-05).
5. Focus ring on the address search field (1px red outline) while focused.

Everything else, including selected saved-place chip, buttons, links, active location label, is neutral blue `#5E8AA8` or white. At most 2 red elements are on screen in normal operation (title bar plus one urgent row). If more than 1 row is urgent, only the soonest gets red countdown text, the others get a red left marker only.

CSS tokens (names are the contract):
`--c-bg #000000`, `--c-surface #08131D`, `--c-frame #1C3A52`, `--c-blue #5E8AA8`, `--c-red #E0202A`, `--c-red-deep #7A0F15`, `--c-text #E8EEF4`, `--c-dim #7E92A3`.

## Layout and Components

Single portrait column, no scrolling chrome. Screen top to bottom:

1. **Title bar** (48px tall, red `--c-red` fill, full width minus `md` gutter, 1px frame). Left: `SHINIGAMI EYES` in Silkscreen 16 black text. Right: 24x24px close-box glyph `×` in a 1px black square, decorative only in Phase 1 (non-interactive, `aria-hidden`). Mirrors the hero "EYES" bar.
2. **OFF-GRID banner slot** (0px when online, 48px when off-grid). Pushes content down. See States.
3. **Location strip** (48px). Left: current place label in Body 16 white (`GPS · Bulleen` style: source word in dim Label 12, place name in Body). Right: `PIN` button (48px tall, 64px wide, 1px frame, blue text, `aria-label="Set location"`) opens the Place Sheet. The row-1 Display 28 countdown is the primary focal point of the main screen. Phase 2 reuses this strip as the map header.
4. **Section header** `NEXT` (Silkscreen 16, blue, 1px bottom rule `--c-frame`). The same container becomes the Phase 2 "next" strip and drawer, so the list is a self-contained `<section class="next-list">` with no knowledge of page chrome.
5. **Item list** (flex column, gap `md`, fills remaining height, `overflow-y: auto`, `overscroll-behavior: contain`). Phase 1 has 2 providers producing about 5 rows (golden hour, blue hour, UV protection until, UV now, plus placeholders only if provider data exists).
6. **Footer line** (24px, Label 12 dim): `server 14:02 · v0.1.0` style freshness for the whole profile. Respects bottom safe area.

### Item Row (the carry-forward component)

Min height 48px (Display row 64px). 1px frame `--c-frame`, background `--c-bg`, padding `sm` vertical, `md` horizontal. Layout is two lines, left to right:

- Line 1: item name (Body 16, white, single line, ellipsis) on the left, countdown right-aligned (Countdown 20 bold, blue by default, tabular-nums).
- Line 2: kind tag (Label 12 dim, e.g. `sun` or `uv`) on the left, freshness tag (Label 12 dim, e.g. `2h old`) right-aligned.
- Row 1 (soonest non-expired) uses Display 28 countdown and 64px min height. Other rows use 20.
- Left edge: 4px solid vertical marker. Blue `--c-blue` normal, red `--c-red` urgent, `--c-frame` stale/expired.
- Row is a button-like element for Phase 2 (tap opens info card). In Phase 1 it is not interactive: no hover state, no pressed state, `cursor` irrelevant, but keep `role="listitem"`.
- Row label format examples, exact: `Golden hour` + `18:42`; `UV protection` + `3h 12m` with kind `uv`; far item `14d 6h`.
- Name text carries the verb implicitly through the countdown, so the name is the state noun only. Example: `Golden hour ends`, `UV protection until`, `Blue hour starts`. The countdown on the right completes it (D-04 examples, `Golden hour: ends in 18:42` is the spoken form).

### Countdown format (D-04, exact)

| Remaining | Format | Tick |
|-----------|--------|------|
| < 1 h | `mm:ss` zero-padded (`18:42`, `00:07`) | every 1 s |
| 1 h to < 24 h | `Hh Mm` (`3h 12m`), no seconds | on minute change |
| ≥ 24 h | `Dd Hh` (`14d 6h`) | on hour change |

Always `target_ts - (Date.now() + serverOffset)`, rendered with `textContent`. One shared 1 Hz tick drives all rows via `requestAnimationFrame`-aligned `setInterval`, and a forced redraw on `visibilitychange` to visible.

### Place Sheet (manual pin, D-08, D-09)

Opens from the `PIN` button as a bottom sheet: black, 1px top frame, slides up 200ms ease-out, max height 70dvh, backdrop `rgba(0,0,0,0.72)` tap to dismiss, Silkscreen header `SET LOCATION`.

Contents top to bottom:
1. Option `Use GPS` (48px row, blue text, shows the active tick `●` when GPS is the current source).
2. Saved places, 4 rows of 48px, in this order: `Home (Bulleen)`, `Monash Clayton`, `Melbourne CBD`, `Hammers Gym Nunawading`. One tap selects and closes the sheet. Active place shows `●` in blue. Home coordinates are server-side only: the client gets only the place id and display name.
3. Address search: 48px input, placeholder `Search address`, 16px font, `autocomplete="off"`, `enterkeyhint="search"`, submit on Enter. Results list under it, up to 5 rows of 48px, name in Body, suburb in Label dim. Debounce 400ms, minimum 3 characters. Tap result selects and closes.

Loading state for search: single Label row `Searching...`. No spinner graphics.

## Interaction and Motion Contract

| Behaviour | Spec |
|-----------|------|
| Cold open | Render from IndexedDB cache synchronously on first paint, target < 1 s (PLAT-03). No splash, no skeleton shimmer. Hero activation is Phase 2 |
| Live fill-in | SSE updates replace rows in place. Row text swaps with no animation. New rows insert with 120ms opacity 0 to 1. No layout jump: list reserves rows by item id |
| Expiry (D-05) | At `remaining <= 0` the row gets class `expiring`: background and left marker flash `--c-red` twice over 600ms (step easing, no smooth blur), then over 400ms opacity falls to 0.35 and the text goes `--c-dim`, then the row collapses (height to 0, 200ms) and is removed from the DOM. Total 1.2 s. The pulse is a state-change effect only, it never repeats |
| Urgent threshold | Under 15 min remaining switches countdown and left marker to red (default). Back to blue if data refresh moves the target later |
| Stale (D-06) | Row at opacity 0.55, countdown and name in `--c-dim`, left marker `--c-frame`, age tag shown. Default stale thresholds: sun times (computed locally) never stale, UV live reading stale after 30 min, any other layer stale after 2x its refresh interval (provider-declared). Stale rows keep counting, they are not hidden |
| Age tag | Always visible, per row, Label 12 dim. Format: `just now` (< 1 min), `5m old`, `2h old`, `3d old`. Computed items show `computed`. Age updates on the minute |
| Foregrounding | On `visibilitychange` visible: recompute all countdowns immediately, request a fresh GPS fix (D-10), then show cached profile while revalidating |
| Location updates | Fresh fix on open and on return to foreground, then only re-profile after movement of about 100 m (D-10). Location label shows `GPS` while fix is live, `PIN` when manual |
| Network timeout | Fetches abort at 4 s. On abort or failure, enter OFF-GRID. Reconnect (successful fetch or SSE open) clears the banner with 200ms fade |
| Reduced motion | Under `prefers-reduced-motion: reduce`, the expiry pulse becomes a single 300ms red fill with no repeat, sheet appears with no slide |
| Press feedback | Buttons and sheet rows: background `--c-surface` while pressed, no transform, no scale. 48px minimum target. `-webkit-tap-highlight-color: transparent` |
| Glitch effects | None in Phase 1 (HUD-09 is Phase 7). No scanlines, no chromatic aberration, no text jitter |

## States

### OFF-GRID (D-07, PLAT-05)

Persistent full-width red banner, 48px, `--c-red` fill, text white `#FFFFFF` at weight 700 (≈4.76:1; black and `#E8EEF4` fail on red). Left aligned with `md` padding. Format, exact: `OFF-GRID · last sync 14m ago` with `OFF-GRID` in Silkscreen 16 and the remainder in JetBrains Mono 12 bold. Never dismissible. `role="status"`, `aria-live="polite"`. The sync age updates every minute. When no sync ever happened: `OFF-GRID · never synced`. Cached rows remain visible beneath and keep ticking, and all rows show their age tag. While off-grid the title bar stays red too (two red surfaces is the accepted maximum for this state).

### Location states

| State | Display |
|-------|---------|
| GPS locating | Location strip shows `GPS · locating...` in dim, list shows cached profile for last known place |
| GPS denied or unavailable | Strip shows `GPS off` dim, Place Sheet auto-opens once per session with the message below |
| Manual pin | Strip shows `PIN · {place name}`, GPS is not requested until `Use GPS` is picked |

### Empty, loading, error

| Case | Treatment |
|------|-----------|
| First run, no cache, online | List area shows 3 placeholder rows with `--` countdowns and `loading` age tags (frames only, no animation) until the first profile arrives |
| First run, no cache, offline | Empty state block (below) plus the OFF-GRID banner |
| No items for this location | Empty state block |
| Provider failed, others fine | The failed layer's rows keep last data with stale styling. If it has no data, no row is shown. No inline error text per row |
| Search error | Single row in results, dim text |

## Accessibility

- Contrast: all text ≥ 4.5:1 on its background (verify `--c-dim` and `--c-blue` at 12px).
- Colour is never the only signal: urgent state also shows the 4px marker plus the 28/20px bold countdown, stale also shows the age tag, off-grid also shows the word `OFF-GRID`.
- Countdown elements are not `aria-live` (would announce every second). Each row has `aria-label="{name}, {countdown}"` refreshed once per minute. The OFF-GRID banner is the only live region.
- Dynamic Type is not honoured in a standalone PWA body at fixed px, so sizes are fixed by this spec.
- Sheet traps focus, closes on backdrop tap, `Escape` for hardware keyboards, labelled by its header.

---

## Phase 2 Carry-Forward Constraints

- `next-list` component takes an array of Item view-models and has no dependency on page chrome, so it can mount inside a map drawer or strip.
- Row anatomy (name, countdown, kind tag, age tag, left marker) is final. Phase 2 adds a tap handler and a map tag counterpart sharing the same tokens.
- Frame, colour, and type tokens in `tokens.css` are final for the app. Phase 2 may add tokens (map layer colours), not change these.
- Title bar is a standalone component so the Phase 2 hero activation can reuse its bar style.
