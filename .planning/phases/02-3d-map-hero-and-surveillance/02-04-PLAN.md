<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| tailnet client → /tiles route | Path params from the phone |
| build.protomaps.com / GitHub releases → CT | Downloaded binary and data |
| refresh job (shinigami user) → /var/lib/shinigami/tiles | Service-writable data dir |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-09 | Tampering | /tiles path params | mitigate | FastAPI int Path params with ge/le, x,y < 2^z check, no filesystem path built from input |
| T-02-10 | Information disclosure | tile request logging | mitigate | No logging in tile route; `--no-access-log` kept in unit (tile URLs encode where David is) |
| T-02-11 | Tampering | go-pmtiles binary | mitigate | Pinned version + hard-coded sha256 verified with `sha256sum -c`; installed root-owned 0755 in /usr/local/bin |
| T-02-12 | Elevation of privilege | refresh-tiles.sh | mitigate | Runs as shinigami (refuses root); root never executes anything from /var/lib/shinigami (CR-01 class) |
| T-02-13 | Denial of service | extract filling the 8 GB disk | mitigate | dry-run first, MIN_FREE_MB guard, tmp then atomic rename, old file kept until verify passes |
| T-02-14 | Denial of service | malformed/unsupported PMTiles | mitigate | Header assertion (MVT+GZIP) → status unsupported, routes return 204, health surfaces it |
</threat_model>
