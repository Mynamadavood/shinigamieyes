<objective>
## Phase Goal

**As a** David (the only user), **I want to** open Shinigami Eyes and watch the red eyes activate onto a dark, tilted 3D map of my surroundings with named tags, info cards and the cameras around me, **so that** I can read my street at a glance, Watch Dogs-style, without any third party learning where I am.

This plan closes UAT gap 1 (major): David flipped PROVISIONAL decision 1 on 2026-11-10. Saved places now show cameras, EXCEPT Home, so Home's location never reaches the phone (camera positions within 150 m of Home would reveal it).

Design (Claude's discretion, stated so executors do not re-decide):
- Per-place flag `cameras` in places.toml (bool, default true). The place whose id is `home` (case-insensitive) or whose label starts with `home` (case-insensitive) is ALWAYS camera-free: a missing flag, or even `cameras = true`, does not enable it (fail closed; log a warning naming only the id). A non-bool flag value is treated as false (fail closed). This means David's real /etc/shinigami/places.toml needs NO edit: no human action.
- Pin profiles still send location.lat/lon = null. The client measures distance and red-tag ranking for pin views from the server-computed `detail.distance_m` that `providers/cameras.py` already sets on every camera item (distance from the place). No place coordinates are added anywhere.
- `/api/places` gains a `cameras` boolean per place (no coordinates) so verify.sh can tell which places should and should not carry camera layers.

Output: server gate, client pin-view tags, updated verify.sh checks, tests with fake coordinates only.
</objective>
