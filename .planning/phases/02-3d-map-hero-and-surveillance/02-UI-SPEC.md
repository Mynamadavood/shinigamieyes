# Phase 2 — UI Design Contract

> Visual and interaction contract for the red-eyes opening, the 3D map HUD, tags, cards, drawer and camera layers. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Extends `01-UI-SPEC.md` (approved). Everything in Phase 1 stays binding unless a row below says "changes". Sources: 02-CONTEXT.md D-01..D-18 (locked), Phase 1 contract and `web/src/styles/tokens.css`, hero-eyes.png and nethack-view.png (style only, recoloured, not traced). Items marked (default) are researcher choices within CONTEXT "Claude's Discretion".
> Target: iPhone portrait standalone PWA, dark only. Reference viewport 393 x 852 pt, top safe inset 59, bottom safe inset 34.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (vanilla TS + Vite, CSS custom properties). shadcn gate not applicable |
| Preset | not applicable |
| Component library | none. Map is `maplibre-gl` 6.x with a hand-authored style JSON; overlays are hand-written DOM modules |
| Icon library | Original self-hosted SVG sprite `web/public/icons.svg` (`<symbol>` + `<use>`), 24 x 24 grid, 2px stroke, square caps and miter joins, `shape-rendering: crispEdges`, `currentColor`. No icon font, no third-party icon set. Symbols: `cctv`, `speed-cam`, `redlight-cam`, `building`, `recenter`, `pin`. Marker art (`figure`, `pin-manual`) is separate inline SVG |
| Font (titles) | Silkscreen 400/700 (unchanged, titles and card headings only) |
| Font (body) | JetBrains Mono 400/700, tabular-nums on every countdown and distance (unchanged) |
| Map glyphs | Self-hosted SDF PBF glyphs generated from JetBrains Mono Regular (`/glyphs/{fontstack}/{range}.pbf`), same origin, service-worker cached. No glyph CDN |
| Tokens file | Extend `web/src/styles/tokens.css` only (additions in "Tokens added" below). No literal hex or px elsewhere, except inside the map style JSON which must read the same values (generate the style from tokens at build, or keep a comment cross-reference) |
| Rendering | Phase 1 rules hold: 1px solid frames, radius 0, no box-shadow, no CSS gradients. Exception: map extrusion `vertical-gradient` is a MapLibre paint property and is allowed. Overlay panels may use rgba backgrounds so the map shows through |
| One WebGL context | Only MapLibre. Hero art, tags, cards, marker, accuracy ring are SVG or DOM. No three.js, no canvas shaders |

## Spacing Scale

Phase 1 scale unchanged (xs 4, sm 8, md 16, lg 24, xl 32, 2xl 48, 3xl 64). All multiples of 4.

| Token (new, composed from the scale) | Value | Usage |
|-------|-------|-------|
| `--drawer-handle` | 24px (lg) | Drag-handle zone height |
| `--drawer-peek` | 144px = lg + 3xl + sm + 2xl | Collapsed drawer: handle 24, Display row 64, gap 8, second row 48. Add `env(safe-area-inset-bottom)` on top |
| `--tag-icon` | 32px (xl) | Full-tag icon box |
| `--tag-icon-compact` | 24px (lg) | Compact-tag icon box |
| `--tag-hit` | 48px (2xl) | Minimum interactive area for every tag (invisible padding around the visual) |
| `--card-w` | 224px (56 x 4) | Info card width (min 192, max 240) |

> Component dimensions (card 192/224/240, readout max 176, label ellipsis 144, handle bar 40) are element sizes, not spacing steps, so they sit outside the 4/8/16/24/32/48/64 scale (all are multiples of 4). Graphic and gesture values (6px pin centre hole, 10px long-press move tolerance) are exempt.

**Primary visual anchor (map screen):** David's red figure marker at ~55% of the visible map height, with the Display-size countdown in the drawer peek as the secondary anchor.
| `--card-gap` | 16px (md) | Distance between tag edge and card edge (leader line length) |

Exceptions: the 1px frame and 1px leader line are border widths, not tokens. Accuracy ring and long-press ring are drawn in metres or px by the map, not layout spacing. All interactive controls keep the 48px minimum (Phase 1); the tag visuals are smaller but their hit area is 48.

|-----------------|-----------|------|

| Tag label | Label | JetBrains Mono 12 / 400, `--c-text`, single line, ellipsis at 144px |

## Screen Layout (map HUD, iPhone portrait)

Z-order, back to front: grid (CSS, behind map) → MapLibre canvas (full-bleed, `position: fixed; inset: 0`, ignores safe areas so the map reaches the screen edges) → overlay HUD (pointer-events none on the container, auto on controls) → tags/marker (map DOM markers) → card → drawer → OFF-GRID banner pushes the HUD column down → hero (above everything during opening).

Overlay column, top to bottom, all padded `--s-md` horizontally and below `env(safe-area-inset-top)`:

| Element | Spec |
|---------|------|
| Top safe area | Solid `--c-bg` fill, height `env(safe-area-inset-top)` |
| Title bar | Phase 1 component, 48px, red, text `SHINIGAMI EYES` white, decorative `×` box. Sits over the map (opaque) |
| OFF-GRID banner slot | Phase 1 behaviour: 0 online, 48px offline, pushes everything below it down by 48 |
| Location strip | Phase 1 strip (48px, `GPS · Bulleen` + `PIN` button 64 x 48) but background `--c-panel` with a 1px bottom rule `--c-frame`, full width. This is where Set location lives |
| Corner readouts, top-left (D-09) | Stacked below the strip, `md` from left and `sm` from the strip. Each readout is a 2-line block: line 1 Label 12 dim name (e.g. `Golden hour ends`), line 2 Countdown 20 bold blue (`18:42`). Max 2 readouts (the 2 soonest non-positioned items, sun/UV). Background `--c-panel`, 1px `--c-frame`, padding `sm` / `md`, width auto, max 176px. Non-interactive. Style cue: Watch Dogs "REMOTE IP / LIVE STREAMING" labels |
| Camera count readout, top-right (D-14, D-16) | Below the strip, right aligned, `md` from right edge, max width 176px, same panel as readouts, Label 12, up to 2 lines. Left of it nothing else. If the two readout columns would overlap (narrow device), the count readout wraps to its own row beneath |
| Map area | Everything else |
| Recenter button | 48 x 48, right edge `md`, bottom = `--drawer-peek` + safe-bottom + `md`, `--c-panel` fill, 1px `--c-frame`, glyph `recenter` 24 blue. Pressed: `--c-surface`. `aria-label="Recenter on me"`. Hidden (display none) while following with bearing 0 and pitch at default; shown after any pan, rotate or pitch change |
| Drawer | Bottom, see Drawer |
| Footer line | The Phase 1 footer (`server 14:02 · v0.1.0`) moves inside the drawer at the bottom of the full list. It is not shown on the map |

Overlay HUD must never cover the marker at default follow framing: with the camera following, David's marker is placed at 55% of the visible map height (set `padding: { bottom: drawerPeek }` and a small top padding) so it clears the drawer and readouts.

## Hero Activation (HUD-03, D-01..D-04)

Plays on every cold open only (fresh page load of the PWA). Never on `visibilitychange` resume or bfcache restore. A module-level flag, not sessionStorage persistence, guards re-play within one page lifetime.

Composition (keeps the reference framing): full-screen `--c-bg` black. Top: the red title bar, 48px, text `EYES` (Silkscreen 16 bold white, left, `md` padding) and the `×` box on the right (24px, 1px white border, white `×`). Below the bar the black field with one letterbox band of eye art, vertically centred at 42% of the screen, full-bleed width, height 128px, preserveAspectRatio `xMidYMid slice`.

Eye art (original SVG, one inline `<svg viewBox="0 0 360 128">`, not traced): two anime-style eyes side by side with sharp upper-lid line, a thick heavy brow shape above each, 3 to 4 sparse hair-strand lines at the left and right edges, a lower lash flick, a large iris circle with a smaller black pupil and one off-centre small notch highlight (`--c-on-red`, 4px). Strokes 2px `--c-red`, brows and lashes filled `--c-red-deep` with `--c-red` stroke, iris fill `--c-red-deep` at rest. No magenta, no pink, no gradients, flat fills only.

Timeline (default, total 1500 ms, plays over real boot: the cached profile and map init run underneath and are never delayed):

| t (ms) | Event |
|--------|-------|
| 0 | Title bar + black field visible. Eyes drawn as closed lids (flat line) |
| 100 to 300 | Lid line and brows draw on with `stroke-dashoffset` (200 ms, linear) |
| 300 to 480 | Eyes snap open: lid `transform: scaleY(0.04 → 1)` in `steps(4)` (180 ms, hard stepped, no smooth ease) |
| 480 to 600 | Red iris flash: iris fill steps `--c-red-deep → --c-red`, plus a full-band red flood rectangle at 35% opacity for exactly 2 frames (≈ 66 ms) then off. Single flash only, never repeated |
| 600 to 1100 | Hold. Iris stays `--c-red`, nothing moves |
| 1100 to 1300 | Cut preparation: eyes shrink to a flat horizontal line (`steps(3)`, 100 ms) and the title bar morphs nothing (it simply persists into the map HUD title bar, same size and position, so the bar does not jump) |
| 1300 to 1500 | Hero layer opacity 1 → 0 (200 ms linear) revealing the map layer, which has been rendering underneath since t = 0 |
| 1500 | Hero element removed from the DOM, focus released, `aria-hidden` removed from the app |

Rules:
- Hard cap 1500 ms. If the map or data is not ready the hero still ends at 1500; the map shows whatever it has (cached tiles or grid) and cached profile rows. The hero never waits on the network and never delays first paint of data (core value: cached profile in < 1 s underneath).
- Skip (D-04): a full-screen invisible `<button aria-label="Skip intro">` covers the hero. Any tap, including the `×` box, jumps immediately to the 200 ms fade-out step (or instant under reduced motion). No visible Skip text.
- `prefers-reduced-motion: reduce` (simplify, do not remove skip): no draw-on, no stepped snap, no flash flood. Show the open red eyes statically for 500 ms, then 200 ms fade, total 700 ms. Skip works identically.
- Photosensitivity: only one 66 ms flash at 35% opacity, no strobing, at most 1 flash per second by construction.
- Audio and haptics: none.
- The hero layer is `role="presentation"` with the skip button as the only focusable element. Screen readers get `aria-label="Shinigami Eyes starting"` on the skip button before it is dismissed.

## Map Camera (HUD-04)

| Property | Value (default) |
|----------|-----------------|
| Projection / view | Mercator, north-up (`bearing: 0`). No DeviceOrientation, no compass UI, no heading rotation |
| Initial camera | `zoom: 17`, `pitch: 60`, `bearing: 0`, centred on David (GPS or active manual pin), with `padding.bottom` = drawer peek so the marker sits at about 55% of the visible height |
| Zoom range | `minZoom: 11`, `maxZoom: 19.5`. Extrusions rendered from z14. Beyond the tile's native max zoom the style over-zooms |
| Pitch | Default 60. User may change with two-finger drag between 0 and 70 (`maxPitch: 70`) |
| Rotate | Free two-finger rotate allowed (D-07). The recenter button (or double-tap on it) resets bearing to 0 |
| Follow | Follow mode on at launch and after recenter: new GPS fixes `easeTo` the centre (400 ms, ease-out). Any user pan, pinch, rotate or pitch gesture turns follow off and reveals the recenter button. Follow does not alter zoom, pitch or bearing after the first set |
| Recenter | Tap: `flyTo` David, zoom 17, pitch 60, bearing 0, 600 ms ease-in-out, follow on. Under reduced motion: `jumpTo` |
| Location source | When the active source is a manual pin (search, preset or dropped), follow tracks the pin; the figure marker is hidden unless GPS is active (see Marker) |
| Re-profile | Unchanged from Phase 1: only after about 100 m of movement |
| Max frame budget | Target 30+ fps on iPhone. `pixelRatio` capped at 2, `antialias: false`, `fadeDuration: 0`, `cooperativeGestures: false`, `renderWorldCopies: false`, `maxTileCacheSize` 100 |

### Coverage and offline (D-08, D-15)

- Tiles cover Greater Melbourne. Outside the extract, tile requests 404 or are empty: treat as uncached and show the grid. Data layers still work. No error toast.
- Offline or tiles unreachable: tiles already seen are drawn from the phone cache. Everything else is the grid look:
  - `--c-bg` background with a CSS square grid behind the transparent map canvas: lines 1px `--c-grid`, cell 32px (`repeating-linear-gradient` is the sole allowed gradient use here as it is a pattern, not a fill), fixed to the screen (does not pan).
  - The map style has no opaque full-screen background layer, so missing tiles reveal the grid.
  - Tags, marker, accuracy ring and readouts render on top as normal.
  - If the entire viewport is uncached, show one centred Label 12 dim line at 60% height: `Map tiles unavailable offline`.
  - OFF-GRID banner behaviour is unchanged (Phase 1). No second banner, no separate map error.

## Pull-up Drawer (D-05)

Bottom sheet over the map. Background `--c-panel`, 1px top border `--c-frame`, radius 0, no shadow. Content: Phase 1 `next-list` component unchanged (same row anatomy, tokens, countdown format, stale and urgent rules).

| State | Height | Content |
|-------|--------|---------|
| Peek (collapsed, default) | `--drawer-peek` (144) + safe-bottom | Handle zone + the 2 soonest rows: row 1 Display (64px), row 2 standard (48px). Rows clipped to this height; no scrolling inside the peek |
| Half | 50dvh | Full list visible from the top, vertical scroll inside the drawer, `overscroll-behavior: contain` |
| Full | `100dvh` minus (safe-top + 48 title bar + banner slot + `md`) | Entire list plus the footer freshness line. Map stays visible in the strip above (title bar remains) |

- Snap points: peek, half, full. Drag the handle zone (hit area 48px: the 24px zone plus 24px of invisible padding above it over the map; `touch-action: none` on it). Release snaps to the nearest point; a flick over 0.5 px/ms goes to the next point in that direction. Snap animation 220 ms ease-out, instant under reduced motion. No bounce.
- Tap the handle zone cycles peek → half → peek. Tap on the map (not on a tag) while half or full collapses to peek.
- Handle visual: 40 x 4 bar, `--c-frame` (`--c-blue` while dragging), centred in the 24px zone.
- List scroll only moves the list when the drawer is at half or full and the list is not at scrollTop 0; at scrollTop 0 a downward drag moves the sheet. At peek, drags anywhere in the drawer move the sheet.
- Rows tap behaviour: rows for items with no map position (sun, UV) have no tap handler and no pressed state. If a future row has `geom`, tap flies the map to it and opens its card (not used in this phase).
- Drawer content stays countdowns only (D-14). Cameras never appear in the drawer.
- Empty drawer: Phase 1 empty state block (`Nothing on the radar`) inside the peek, collapsed to the heading plus one line.
- `role="region"`, `aria-label="Next up"`. Handle is a `button` with `aria-label="Expand next up"` / `"Collapse next up"` and `aria-expanded`.

## Floating Tags (HUD-05, D-11, D-13)

Each positioned item with `geom` renders one tag as a MapLibre DOM marker (cap: 60 DOM markers total, nearest first; extras are not rendered).

### Anatomy

| Part | Spec |
|------|------|
| Anchor | The tag's icon box centre sits on the item's coordinate. No pin stem (NetHack flat look). A 1px 8px-tall tick below the icon box points to the exact spot |
| Icon box | `--tag-icon` 32px square, 1px frame `--c-blue`, background `--c-panel`, glyph 24px centred in `--c-blue` |
| Label chip (full tag only) | Directly right of the icon box, 32px tall, 1px frame `--c-blue`, `--c-panel`, padding 0 `sm`, Label 12 `--c-text`, `ellipsis` at 144px. Joined to the icon box with no gap (shared border) |
| Hit area | Wrapper `min-width/height 48px` centred on the visual, transparent, includes the label chip. `role="button"`, `tabindex="0"` |
| Compact tag | Icon box only, `--tag-icon-compact` 24px, glyph 16px. Hit area still 48px |
| Near state (red, ≤ 30 m) | Icon box frame, glyph and tick `--c-red`; label chip fill `--c-red-deep`, frame `--c-red`, text `--c-on-red` weight 700. Compact tags also go red if ≤ 30 m (but ranking puts them first so they become full tags) |
| Pressed | Icon box and chip fill `--c-surface`. No transform |
| Selected (card open) | Frame 2px is not used (frame is 1px only); selected tag shows a 4px `--c-blue` underline bar under the chip (red bar when near state) |

### Budget and promotion (D-11)

- Up to 20 labelled (full) tags on screen at once. Ranking: 1) within 30 m (red for the 3 nearest), 2) nearest by distance from David, 3) severity (reserved for later layers). The remaining tags render compact.
- Compact tags expand to a labelled tag at map zoom ≥ 17.5 only if the total labelled count stays ≤ 20 (nearest-to-screen-centre first). Never exceed 20 labelled tags.
- Collision: if a full tag's rectangle overlaps a higher-ranked tag's rectangle, demote it to compact. Re-evaluate on `moveend` (not every frame), debounced 100 ms.
- Distance is measured from David (the active location), not from screen centre.

### Label copy

| Item | Label |
|------|-------|
| CCTV camera | `Camera` (default). If OSM gives an operator under 16 chars: `Camera · {operator}` is not used on the tag; the operator goes on the card |
| Speed camera | `Speed camera` |
| Red-light camera | `Red-light camera` |
| Manual pin | no tag (it has its own marker) |

Tags show no countdown (cameras are positioned facts, D-14). A future timed positioned item adds a second line `Label 12 blue` countdown inside the chip; not needed this phase.

### Accessibility for tags

- `aria-label="{type}, {distance} away"` (e.g. `CCTV camera, 42 metres away`; `Speed camera, 640 metres away`).
- Tag container `role="group" aria-label="Map tags"`. Keyboard: Tab through tags in rank order; Enter or Space opens the card.
- Colour not the only signal: near state also uses weight 700 label and the word is unchanged; the card repeats the exact distance. Red-state tag is also larger text weight.

| 1 | `1 camera · 150 m · mapped, not exhaustive` |

## Position Marker and Manual Pin (D-07, D-17)

### David's marker (GPS source)

- Original small suited-figure silhouette, 32 x 32 viewBox, solid `--c-red` fill with a 1px `--c-bg` outer outline so it separates from buildings. Shape: round head, shoulders and torso as a wedge-shaped suit jacket with a narrow V lapel notch cut out, one short straight tie notch, legs as a simple trapezoid. No face, no weapon, no hair details, no resemblance to any existing character. Anchor: bottom centre.
- Accuracy ring: a map circle layer at the GPS fix in metres, fill `--c-acc-fill`, 1px `--c-acc-line`. Minimum drawn radius 16px, maximum capped at 150px of screen radius. Hidden when accuracy ≤ 10 m. No pulsing, no animation.
- Hidden while the active source is a manual pin or preset place; shown again on `Use GPS`.
- Hit area 48px. Tap shows a small card (same card style, no leader): `YOU` / `GPS · accuracy 12 m`.
- `aria-label="Your position, accuracy 12 metres"`.

### Manual pin (D-07)

- Marker: 32 x 32 upright pin glyph, `--c-blue` fill, 1px `--c-bg` outline, a 6px `--c-bg` centre hole. Anchor bottom centre. Hit area 48px. Not red.
- Long-press to drop: hold 500 ms on empty map. Movement over 10px cancels. While holding, a 1px `--c-blue` ring grows from 8px to 32px radius at the touch point over 500 ms (linear). At release time the pin appears at that spot (no drop animation; none under reduced motion). The map ignores the long-press as a pan. Suppress the iOS callout and text-selection menu on the map (`-webkit-touch-callout: none; user-select: none`).
- Dropping a pin: becomes the active location (source `search`/manual per D-07), replaces any prior pin, switches the location strip to `PIN · Dropped pin`, triggers a re-profile for that spot, turns follow to the pin. Coordinates come from the client. Haptics: none (iOS web has no vibration).
- Tap the pin: card `YOUR PIN` / `Dropped pin` / secondary Label 12 dim `Set from the map` and a 48px button `Use GPS` (frame blue, text blue) that clears the pin and returns to the GPS source. Clearing a pin is non-destructive (nothing is lost), so no confirmation.
- Pins from address search or presets reuse the same blue marker with the name in the card title.
- Pinned saved places such as Home never reveal server-held coordinates; Phase 1 CR-02 stands (the client shows presets at the 0.1 degree cell, not exact coordinates, and does not drop a precise Home marker).

## Accessibility

- Touch targets: every tag, marker, recenter button, drawer handle, location button, pin-card button has a ≥ 48 x 48 hit area (visuals may be smaller, 24 or 32px, with transparent padding). Overlapping 48px hit areas between adjacent tags: nearest tag centre wins; compact tags in dense clusters (more than 6 within 96px) are rendered at most 6, nearest first.
- Contrast: all HUD text ≥ 4.5:1 on `--c-panel` over any map pixel (panel is 88% black). White on red `#E0202A` ≈ 4.76:1; white on `--c-red-deep` ≈ 11:1; `--c-dim` ≈ 6.5:1; `--c-blue` ≈ 5.7:1. Street-name labels are decorative and exempt.
- Colour is never the only signal: near-camera state adds weight 700 label and distance in the card; the selected building adds the card; stale and urgent rules unchanged.
- Each tag has an `aria-label` with type and distance; cards `role="dialog"` with focus moved in and restored; the OFF-GRID banner remains the only `aria-live` region; countdown readouts are not live (each readout has `aria-label="{name}, {countdown}"` refreshed once a minute).
- Map canvas: `aria-label="3D map of your surroundings"`, `role="application"`; the tag list and drawer provide the non-visual equivalents. Keyboard (hardware): arrows pan (MapLibre default), Escape closes the card, Tab order: title bar skip, location button, tags, recenter, drawer handle.
- Reduced motion: handled throughout (see Motion). No flashing beyond one 66 ms low-opacity frame pair in the hero, which is skipped entirely under reduced motion.
- Fixed pixel sizes (no Dynamic Type), as Phase 1.
- Long-press has an alternative path: the Place Sheet address search and `PIN` button remain.
